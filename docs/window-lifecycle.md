# 窗口生命周期协议

## 为什么叫「窗口」

窗口 = 一次独立对话 = 一次可以提取经验的完整交互周期。

## 状态机

```
        window_open
            │
            ▼
    ┌─────────────────┐
    │   ACTIVE         │  ← 加载历史规则到工作区
    │   (对话进行中)    │  ← 持续心跳检测转折点
    └────────┬────────┘
             │
        window_close
             │
             ▼
    ┌─────────────────┐
    │   CLOSING        │
    │   (收经验阶段)    │
    │   ① 扫描对话日志  │
    │   ② 识别纠正行为  │
    │   ③ 找根因       │
    │   ④ 生成规则     │
    │   ⑤ 去重入库     │
    └────────┬────────┘
             │
    ┌────────▼────────┐
    │   CLOSED         │
    │   (等待下次开窗) │
    └─────────────────┘
```

## 触发条件

### 开窗触发
- 用户打开一个新对话
- 用户切换到一个现有线程
- 用户说「分析一下」

### 关窗触发
- 对话结束/用户离开
- 用户明确关闭/切换线程
- 手动执行 `window close` 命令

### 心跳触发
- 每 N 轮对话检查一次
- 识别到「用户纠正 AI」的节点 → 标记为潜在经验点

## 规则生命周期

```
[新建] → [hit_count=1] → [hit_count≥3 自动强化] → [与其他规则合并] → [归档]
```

- 新规则：置信度从 hit_count=1 开始
- 强化条件：同一规则被命中 3 次以上 → 自动检查能否合并或升级
- 合并条件：两条规则根因重叠度 > 60%
- 归档条件：规则超过 90 天未被命中 → 移入冷存储
